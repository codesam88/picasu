## Notes

Gate the `/get/test/` probe **registration** out of every non-test route table
with `#[cfg(test)]`. Adopted as I6 decision 4 of
`.plan/openapi-contract-hardening.md` after the user's review (the earlier
"backlog, not required" framing is superseded) and **scheduled first** in that
plan's sequence, before I3 and I2 shape exclusions:

- The two probes (`probe_record`, `probe_dupe_group`) are annotated, register
  unconditionally in `generate_get_routes()` (`backend/src/router/get/mod.rs`)
  and are inert outside tests — `probe_enabled()` returns false, so production
  requests 404. After the gate the routes are absent instead of inert; the
  shipped behavior stays 404 either way.
- Shape: `routes!` takes paths only (rocket_codegen grammar), so this is a
  `#[cfg(test)]`-gated extension of the route list, not an `#[cfg]` on an entry.
  Watch `unused_mut` on the base list in non-test builds.
- Unchanged on purpose: handlers and annotations stay compiled (generation is
  cfg-blind and the one generated `openapi.rs` must serve test builds), so the
  full spec keeps the probe paths, the `openapi_public` strip stays, and the
  probe contract tests and in-crate parity tests keep working — unit tests run
  with `cfg(test)` active, so their route table still mounts the probes.
- What the gate buys: no `/get/test/` entry in `--check-openapi`'s drop rule
  (I2), no `--exclude-prefix /get/test/` for the CLI (I1's walk skips
  `#[cfg(test)]` items). The parity filter keeps `is_test_only_path` for the
  test rocket.
- Verification: `just openapi-gen` must be byte-identical (no regeneration
  diff); backend tests, clippy `-D warnings`, `just openapi-check` green.

## Progress

- 2026-09-28: Gate implemented. `generate_get_routes()`
  (`backend/src/router/get/mod.rs`) now builds the base list as
  `let mut routes = routes![...]` under
  `#[cfg_attr(not(test), allow(unused_mut))]`, then appends the two probes
  under a statement-level `#[cfg(test)]` on a `routes.extend(...)` call whose
  argument is a nested `routes![...]`. The cfg is syntactic, so `syn` sees it
  and the nested block is still found by `build.rs` generation — that is what
  keeps both probe paths in `openapi.rs` and the spec; `backend/openapi.json`
  regenerated byte-identical. Non-test builds gained a `dead_code` finding for
  the now-unregistered handlers, silenced with
  `#[cfg_attr(not(test), allow(dead_code))]` on `pub mod get_test_probe` —
  handlers and annotations stay compiled in every build, only the registration
  is gated. TDD: new integration test `backend/tests/probe_registration.rs`
  (`non_test_route_table_mounts_no_probe`) builds the non-test route table via
  `build_rocket_with_config(AppConfig::default())` and asserts no
  `/get/test/` path is mounted; it failed before the change listing both probe
  paths and passes after. Deviation: the suggested HTTP observable does not
  exist in Rocket 0.5 — a wrong-method request on a known path answers 404,
  not 405, so `POST /get/test/...` is 404 both before and after the gate; the
  route-table assertion is the strongest available check. Stale text updated:
  `openapi_public.rs` (`is_test_only_path` doc), `get_test_probe.rs` header
  doc (registration gated, handlers stay compiled for generation), and the
  `openapi_contract.rs` exclusion comment; `docs/test-strategy.md` makes no
  claim about the probes being mounted in every build, so it was left alone.
  Verified: `cargo fmt --check`, `just backend-check` (clippy `-D warnings`),
  `cargo test -p picasu` (319 lib + integration tests green, probe contract
  and parity tests unchanged), `just openapi-gen` + empty
  `backend/openapi.json` diff, `just openapi-check`, `just plan-lint`,
  `just docs-check`. Note: `cargo clippy -p picasu --all-targets` with
  `-D warnings` fails with ~103 pre-existing violations in other test and
  module files on this branch (none in the files touched here); the repo's
  own gate (`just backend-check`) does not use `--all-targets`.
