# Reachability registry — backend/build/reachability.rs, gated by
# src/tests/reachability.rs (`cargo test --lib`, `just test`).
#
# One entry per line, tab-separated:
#   kind<TAB>file<TAB>function<TAB>subject<TAB>snippet<TAB>reason
# kind is the sink/guard class (taint-expect, taint-index, guard-never-read, …);
# subject is the seeding request parameter for sinks, `binding:GuardType` for
# guards. The key is kind+file+function+subject+snippet — no line number, so an
# edit above a site does not churn the registry; a changed key fails as
# new+stale instead. The gate fails when the analysis reports an unregistered
# (new) site or when an entry no longer matches a finding (stale). Every entry
# carries a reason; the leading [class] tag groups entries by whether the taint
# is genuinely request-driven or an artefact of the analysis (pass-through /
# false-positive), so the counts per class can be audited.
#
# Seeded from the analysis output on 2026-09-26 (78 sinks + 9 guards).
# Classes present: false-positive 84, pass-through 3, request-driven 0 — no
# known request-to-panic path is currently reachable; the two historical bugs
# that motivated this gate are fixed (see .plan/request-taint-reachability-gate.md).
