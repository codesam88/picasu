# Accepted breaking OpenAPI changes for `just openapi-breakcheck`.
#
# Each non-comment line names one explicitly approved break that oasdiff
# would otherwise fail on (method + path + change description, backticks
# significant). Add a dated line here — never delete the gate — when a
# breaking spec change is approved. See `.plan/api-assurance.md` step 1.
#
# Only findings that would FAIL the gate belong here: oasdiff prints every
# finding regardless (including warning-class ones like request-property
# removals), and an entry for a non-failing finding gates nothing — dead
# lines were removed 2026-10-26 by deletion-testing each entry.

# 2026-10-26 (config field cleanup, decided): `GET /get/config` drops
# `imagePath` (host-only; admin UI reads it from `GET /get/admin/config`),
# `hasAuthKey` (no consumer; rotation feedback stays on the POST response)
# and `disableImg` (frontend-only preference now, no backend setting).
# `uploadFolder` is relative to the image path and visible to every tier,
# so no redaction remains on the endpoint. `PUT /put/admin/config` and the
# admin export lose the `disableImg` property the same way.
GET /get/config removed the required property `hasAuthKey` from the response with the `200` status
GET /get/config removed the required property `disableImg` from the response with the `200` status
GET /get/admin/config/export removed the required property `config/disableImg` from the response with the `200` status
PUT /put/admin/config removed the required property `config/disableImg` from the response with the `200` status
GET /get/config/export removed the media type `text/plain` for the response with the status `200`

# 2026-10-31 (/links -> /shares rename, decided): the client route moved and
# the frontend asserts no /links legacy, so the backend shell route moves
# with it. Old /links bookmarks fall through to the JSON 404 like any other
# unknown one-segment path.
api path removed without deprecation in API GET /links

# 2026-10-27 (contract correction, decided): `GET /get/admin/config` loosens
# the entry `value` from `object` to `any`. The handler has always returned
# scalars there (string/number/bool per tier); the object declaration was
# wrong and failed response-schema validation, so the loosening is the fix
# rather than a capability removal.
GET /get/admin/config the `items/value` response's property `type` changed from `object` to `any` for status `200`

# 2026-10-30 (share write removal, decided): `PUT /put/set_album_title`,
# `PUT /put/set_user_defined_description` and `POST /upload` no longer
# accept share credentials; shares are read-only and these writes require
# a session. The `album_id AND share_id` scheme removal is the intended
# capability drop, not an annotation slip.
PUT /put/set_album_title the endpoint scheme security `album_id AND share_id` was removed from the API
PUT /put/set_user_defined_description the endpoint scheme security `album_id AND share_id` was removed from the API
POST /upload the endpoint scheme security `album_id AND share_id` was removed from the API
